# 决策一致性协议（Decision Consistency Protocol, DCP）

> 面向多 Agent 并行协作的决策一致性协议：用**可执行的版本门禁**防止认知漂移，用**按承诺强度分级的升级阶梯**控制协调成本。

DCP 解决的是一类具体问题：多个 Agent 并行工作时，各自可能依据过时或片面的信息行动（**认知漂移**），而把所有问题都拿去开会的成本又无法接受。协议给出的答案不是"多开会"，而是：

1. **先分级**——大多数问题根本不需要升级；
2. **再留痕**——每一级答复都留下可审计的记录；
3. **最后上硬门禁**——写类操作在执行前由宿主代码校验依据版本与依据类型，不依赖模型自觉。

## 核心设计

| 机制 | 一句话说明 |
|---|---|
| 五级升级阶梯 L0–L4 | 按**承诺强度**而非影响范围排序：自决 → 信息 → 单点承诺 → 全局约定 → 多方决议 |
| 可引用性 | L1 信息记录**不可**作为写依据；L2 承诺记录必须 `Binding=true` 且 `OwnerId` 非空；L3/L4 决议版本化 |
| 决策日志与版本硬门禁 | 写操作前比对依据版本；过期则拒绝并把差异回灌，要求重新对齐 |
| 结论订阅 | 所有 Worker 订阅决议摘要；有异议走正常升级通道，不设旁听与举手 |
| 异步安全点 | 只在工具调用之间响应协调消息，绝不打断进行中的操作 |
| 人类介入深度轴 | 免批准开会（开关 A）、免事后审核（开关 B）、断路器只自动收回 B、人控模式为"拉满"档 |
| L2 定向咨询 | 由责任域 owner 作出可被依赖的单点承诺；不递增版本，但可被引用 |

## 一个例子

假设 Worker A 要修改 `parse()` 的行为：

| A 的问题 | 判定 | 处理 |
|---|---|---|
| "空输入时 `parse()` 返回 null 还是抛异常？" | **L1 信息** | 查代码/记录即可；答复落一条轻量记录，**不可引用为写依据** |
| "我要长期依赖这个行为不变" | **L2 单点承诺** | 找该模块责任域 owner 确认；记录 `Binding=true`，可引用 |
| "我能改 `parse()` 的签名吗？" | **L3 全局约定** | 主控裁决 + 广播 + 决策日志版本递增 |
| "日志用 JSON 还是文本？两个方案互斥且影响多方" | **L4 多方决议** | 开会；决议写日志 + 广播 |

关键差别不在"问了谁"，而在**答复能不能作为别人写操作的依据**：L1 说错只误导提问者，L2 说错会让依赖它的写操作全部建立在错误前提上。后者才是门禁要管的东西。

## 协议与实现无关

本仓库只定义协议，不绑定任何 harness、框架或运行时。宿主只要具备 [规范 §17](docs/specification.md#17-宿主能力要求实现无关) 列出的能力（安全点、可拦截的写路径、持久化日志、消息投递、待答队列、责任人登记等），就可以实现 DCP。

DCP **不是**共识算法（Paxos/Raft 那类），也**不是**安全边界：它假定参与者是合作的，负责防止"依据过时的写"，不负责防止恶意节点；执行层门禁是策略守卫，不是不可绕过的安全隔离。

## 文档状态

- 协议版本：**v1.0**（2026-10-19）
- 来源：协议最初在作者的个人 AI coding harness 项目中提出并迭代；本仓库是其独立化整理，宿主实现细节已剥离，机制定义保持可验证。
- **L2 是暂定层级**：须先经触发率前置测试（规范 §15.7）验证。若承诺类议题占比过低，按规范 §2.4 将 L1/L2 合并为一级咨询（用 `Binding` 字段区分事实与承诺），编号收缩为 L0–L3，而不是直接删除。
- L4 会议是协议中成本最高的一层，建议在核心层（L0–L3 + 决策日志 + 版本门禁）稳定后再落地。
